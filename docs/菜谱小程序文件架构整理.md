# 菜谱小程序文件架构整理

日期：2026-05-14

## 1. 整理目标

本文件用于把当前“点单系统遗留结构”整理为“朋友菜谱小程序结构”。

整理目标有三个：

1. 让目录结构直接表达新业务：菜谱、想吃请求、收藏、用户、管理。
2. 让旧业务逐步退出主线：商品、购物车、订单、价格、库存、店铺。
3. 让后续 CloudBase 迁移有明确落点，不在旧 Express/MySQL 结构里继续加复杂度。

本次整理已经进入落地阶段：不再保留旧点单系统主链路，也不再保留 `legacy/` 作为过渡目录。后续新增内容必须继续围绕菜谱、想吃请求、收藏、留言、用户和轻量管理展开。

## 2. 已清理的问题

整理前目录里同时存在三套业务语义：

```text
点单系统：
menu / product / cart / order / orders / admin/orders

菜谱系统：
pages/recipes/*
server/models/Recipe*

扩展玩法：
blind-box / reminders / game
```

这些问题已经从当前主线中清理：

1. 当前 `pages/` 已收敛为菜谱、想吃请求、用户和管理页面。
2. 当前 `app.json` 不注册旧点单页面。
3. 当前主线不再依赖 Express/MySQL。
4. 当前代码不保留购物车、订单金额、价格、库存等商业点单概念。
5. 盲盒、提醒、游戏化等扩展入口不再保留在第一版目录中。

## 4. 页面目录整理

### 4.1 首页

目标路径：

```text
pages/home/home.js
pages/home/home.wxml
pages/home/home.wxss
pages/home/home.json
```

职责：

1. 展示已发布菜谱列表。
2. 搜索菜谱。
3. 分类筛选。
4. 最新/热门排序。
5. 进入菜谱详情。

迁移来源：

```text
pages/menu/menu.*
pages/recipes/list/list.*
```

整理原则：

1. 不再叫 `menu`。
2. 不展示“月售”“好评率”“店铺”等商业字段。
3. 首页卡片统一使用 `recipe-card` 组件。

### 4.2 菜谱详情

目标路径：

```text
pages/recipe/detail/detail.js
pages/recipe/detail/detail.wxml
pages/recipe/detail/detail.wxss
pages/recipe/detail/detail.json
```

职责：

1. 展示菜谱主图、标题、作者、描述。
2. 展示食材和步骤。
3. 收藏菜谱。
4. 发起“想吃”请求。
5. 作者或管理员可以编辑菜谱。

迁移来源：

```text
pages/product/product.*
pages/recipes/detail/detail.*
```

整理原则：

1. 不再使用 `product`。
2. 不出现价格、规格、加入购物车。
3. 主按钮改成“想吃这个”。

### 4.3 发布和编辑菜谱

目标路径：

```text
pages/recipe/edit/edit.js
pages/recipe/edit/edit.wxml
pages/recipe/edit/edit.wxss
pages/recipe/edit/edit.json
```

职责：

1. 新建菜谱。
2. 编辑菜谱。
3. 上传主图。
4. 添加食材。
5. 添加步骤。
6. 保存草稿。
7. 发布菜谱。

迁移来源：

```text
pages/recipes/create/create.*
```

整理原则：

1. 新建和编辑共用同一页面。
2. 通过 `id` 参数判断编辑模式。
3. 表单组件抽到 `components/recipe-form/`。

### 4.4 我的请求

目标路径：

```text
pages/requests/list/list.js
pages/requests/list/list.wxml
pages/requests/list/list.wxss
pages/requests/list/list.json
```

职责：

1. 展示我发起的想吃请求。
2. 展示请求状态。
3. 取消待处理请求。
4. 跳回菜谱详情。

迁移来源：

```text
pages/orders/orders.*
pages/order-detail/order-detail.*
```

整理原则：

1. 不再叫 `orders`。
2. 请求状态使用 `request-status.js` 常量。
3. 列表卡片使用 `request-card` 组件。

### 4.5 收到的请求

目标路径：

```text
pages/requests/manage/manage.js
pages/requests/manage/manage.wxml
pages/requests/manage/manage.wxss
pages/requests/manage/manage.json
```

职责：

1. 作者查看自己收到的想吃请求。
2. 管理员查看全部请求。
3. 更新请求状态。

迁移来源：

```text
pages/admin/orders/orders.*
pages/order/order.*
```

整理原则：

1. 不再使用“订单管理”。
2. 状态流转只保留 `pending -> accepted -> preparing -> done` 和 `pending -> declined`。
3. 页面里不展示价格、总金额、取餐。

### 4.6 我的页面

目标路径：

```text
pages/user/profile/profile.js
pages/user/profile/profile.wxml
pages/user/profile/profile.wxss
pages/user/profile/profile.json
```

职责：

1. 展示用户资料。
2. 进入我发布的菜谱。
3. 进入我收藏的菜谱。
4. 进入我的请求。
5. 进入收到的请求。
6. 管理员显示管理入口。

迁移来源：

```text
pages/user/profile/profile.*
```

整理原则：

1. 保留当前页面，但去掉直接请求 Express 的写法。
2. 用户资料改为云开发用户模型。

### 4.7 管理页

目标路径：

```text
pages/admin/admin/admin.js
pages/admin/admin/admin.wxml
pages/admin/admin/admin.wxss
pages/admin/admin/admin.json
pages/admin/categories/categories.*
pages/admin/recipes/recipes.*
```

职责：

1. 管理分类。
2. 管理全部菜谱。
3. 查看全部请求入口。
4. 轻量统计。

迁移来源：

```text
pages/admin/admin.*
pages/admin/menu/menu.*
pages/admin/store-config/store-config.*
```

整理原则：

1. 后台只服务小范围管理，不做商业报表。
2. `store-config` 迁移为平台基础设置，第一版可以先不做。

## 13. 最终结构验收标准

当文件架构整理完成后，应满足：

1. `pages/` 目录只包含第一版正在使用的页面。
2. `app.json` 中没有旧点单页面。
3. 页面代码不再调用 `http://localhost:3000/api`。
4. 业务代码不再出现 `price`、`checkout`、`payment`、`sales`。
5. 不存在 `server/`、`database/`、`legacy/` 等旧过渡目录。
6. 云函数负责权限敏感读写操作。
7. 页面通过 `services/` 访问数据。
8. 常量统一从 `constants/` 引入。
9. 旧文件已删除，不再以 `legacy/` 形式继续保留。
